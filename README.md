# Проект по загрузке банковских данных из CSV файлов и построению витрин данных для отчетности.

## Структура проекта

### Часть 1: Загрузка данных и расчет витрин

#### Задание 1.1 - ETL загрузка из CSV
- Загрузка 6 CSV файлов в PostgreSQL
- Обработка разных форматов дат
- UPSERT стратегия для всех таблиц
- Логирование в таблицу LOGS.ETL_LOG

#### Задание 1.2 - Расчет витрин оборотов и остатков
- Создание витрин DM.DM_ACCOUNT_TURNOVER_F и DM.DM_ACCOUNT_BALANCE_F
- Процедура расчета оборотов с учетом курсов валют
- Процедура расчета остатков для активных и пассивных счетов
- Расчет за январь 2018 года

#### Задание 1.3 - Форма 101
- Создание витрины DM.DM_F101_ROUND_F
- Процедура расчета формы 101 за отчетный период
- Группировка по балансовым счетам второго порядка
- Разделение на рублевые и валютные счета

#### Задание 1.4 - Экспорт и импорт CSV
- Экспорт витрины в CSV файл с заголовками колонок
- Импорт данных из CSV в новую таблицу
- Изменение данных в CSV и повторный импорт
- Логирование операций экспорта и импорта

### Часть 2: Исправление дефектов данных

#### Задание 2.1 - Устранение дублей в витрине dm.client
- Обнаружение дублирующихся записей по ключевым полям
- Удаление дублей с использованием CTID и оконных функций
- Добавление уникального ограничения для предотвращения новых дублей

#### Задание 2.2 - Восстановление данных в витрине dm.loan_holiday_info
- Загрузка актуальных CSV файлов в слой RD
- Анализ пропущенных периодов в витрине
- Полная перезагрузка витрины (TRUNCATE + INSERT)
- Создание процедуры для автоматического обновления

#### Задание 2.3 - Исправление данных в витрине dm.account_balance_turnover
- Анализ несходящихся остатков по счетам
- Исправление account_in_sum на основе предыдущего дня
- Исправление account_out_sum на основе следующего дня
- Перестроение витрины с корректными данными
- Создание процедуры для регулярного обновления

## Технологии
- PostgreSQL (схемы: DS, DM, RD, LOGS)
- Python (psycopg2, pandas)
- PL/pgSQL (процедуры и функции)

## Логирование
Все ETL операции логируются в таблицу LOGS.ETL_LOG с указанием:
- времени начала и окончания
- количества затронутых записей
- статуса выполнения (SUCCESS/ERROR)
- текста ошибки (при наличии)
